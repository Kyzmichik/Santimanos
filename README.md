# Santimanos — MVP-1…MVP-4B

Платформа пошуку майстрів і замовників (Flask + SQLite). Технічне завдання — у `TZ.md`.

## Запуск

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Відкрийте http://127.0.0.1:5000. Під час першого запуску створюються `santimanos.db` і довідник категорій.

## Що вже є (MVP-1)

- Реєстрація, вхід, вихід (пароль хешується, CSRF-захист на всіх формах).
- Особистий кабінет: особисті дані, аватарка (перевірка, обрізання до квадрата, перекодування), приватність телефону й прізвища, видалення акаунта.
- Режим майстра та резюме: заголовок, опис, досвід, графік, райони, категорії, послуги з цінами, портфоліо до 20 фото.
- Публічна сторінка-резюме `/masters/<id>` з урахуванням приватності.
- Каталог `/masters`: пошук, категорія, район, ціна, сортування, пагінація.

## Що додано в MVP-2

- **Заявки** `/requests/new`: категорія, опис, фото (до 5), район, бажана дата, бюджет.
- **Стрічка заявок для майстрів** `/requests/`: за їхніми категоріями (є перемикач «усі категорії»).
- **Пропозиції майстрів** з ціною й коментарем; майстер може відкликати пропозицію, доки його не обрано.
- **Статуси:** нова → в обговоренні → в роботі → виконана / скасована. Замовник обирає виконавця й сам позначає заявку виконаною.
- **Відгуки** `/requests/<id>/review`: оцінка 1–5, тип «Похвала» / «Скарга», текст, фото.
  - Лише замовник виконаної заявки, один відгук на заявку.
  - Заборонені телефони, посилання, email і нецензурна лексика.
  - Редагування 48 годин; кожна зміна пишеться в історію (`review_edits`).
- **Публічна відповідь майстра** (одна на відгук).
- **Скарга на відгук** → таблиця `reports` (черга для модератора в MVP-3).
- **Рейтинг:** середня оцінка, розбивка по зірках, бейдж «Багато виконаних робіт» (5+), фільтр «рейтинг від» і сортування за рейтингом та кількістю відгуків.
- Кабінет: вкладки «Мої заявки», «Стрічка заявок», «Відгуки».

Якщо у вас уже є `santimanos.db` з MVP-1, залиште її: нові таблиці створяться автоматично, існуючі не змінюються.

## Що додано в MVP-3

- **Чат** `/messages`: діалог замовник ↔ майстер (текст + фото), лічильник непрочитаних у меню, автооновлення сторінки діалогу кожні 8 секунд. Почати діалог можна з профілю майстра або із сторінки заявки.
- **Телефон** можна показувати: усім / зареєстрованим / **після того, як мені напишуть** / нікому.
- **Email-сповіщення:** нове повідомлення (лише на перше непрочитане), нова пропозиція до заявки, вибір виконавця, новий відгук. Вимикаються в кабінеті.
- **Підтвердження email** і **відновлення пароля** (одноразове посилання на 1 годину), зміна пароля в кабінеті.
- **Ліміти запитів** на вхід, реєстрацію, відновлення пароля й повідомлення.
- **Адмін-панель** `/admin`:
  - статистика;
  - користувачі (пошук, блокування, підтвердження особи майстра);
  - черга скарг на відгуки й профілі (приховати відгук, відхилити скаргу, історія змін відгуку);
  - категорії й райони.
- Бейдж «Особу підтверджено» в каталозі й на резюме. Заблокований користувач не може увійти, а його профіль зникає з каталогу.
- Старі бази оновлюються автоматично (`app/dbupgrade.py`).

## Що додано в MVP-4A (зручність)

- **Сповіщення майстрам про нові заявки** у їхніх категоріях. Режим обирається в «Моє резюме»: одразу на email, раз на день (дайджест) або вимкнено.
- **Особисті заявки:** кнопка «Запропонувати заявку» на профілі майстра надсилає заявку саме йому. Інші майстри її не бачать. Якщо майстер відхиляє запрошення, заявка відкривається для всіх майстрів у категорії, а замовник отримує листа.
- **Підказки у формі заявки** залежно від категорії (що варто вказати: площа, тип покриття тощо). Адмін редагує їх у розділі «Категорії».
- **Обране:** кнопка «☆ В обране» на профілі майстра і вкладка «Обране» в кабінеті.
- **«Замовити ще раз»** для виконаних і скасованих заявок, а також «замовити ще раз у цього майстра».

## Що додано в MVP-4B (зростання)

- **Головна:** блоки «Топ майстрів» і «Останні відгуки». Топ рахується за зваженим рейтингом: поки відгуків мало, оцінка «підтягується» до 4.0, тож один відгук на 5★ не обганяє 4.9 зі ста відгуків (`PRIOR_MEAN`, `PRIOR_WEIGHT` у `app/catalog.py`).
- **Сторінки для Google** (`app/seo.py`):
  - категорії `/services/12-plytka`, міста `/city/madryd` і їх поєднання `/services/12-plytka/madryd`;
  - хаб `/services` з усіма послугами й містами;
  - адреси транслітеровані; число в адресі — id категорії, тож після перейменування в адмінці стара адреса перенаправляє на нову (301);
  - міста беруться з профілів майстрів («Мадрид» і «мадрид » — одне місто);
  - `sitemap.xml` (лише сторінки, де є майстри) і `robots.txt`;
  - мета-опис, canonical і Open Graph на кожній сторінці; порожні сторінки й відфільтрований каталог мають `noindex`.
- Категорії на головній, на сторінці майстра й у футері ведуть на ці сторінки. У каталозі з'явився фільтр «Місто», у формі заявки — підстановка категорії через `?category=`.
- **PWA:** сайт можна встановити на телефон (маніфест, іконки, кнопка «Встановити застосунок» у футері). Service worker кешує лише статику й сторінку «Немає з'єднання»; особисті сторінки не кешуються.
- **Telegram-сповіщення:** у кабінеті «Підключити Telegram» → бот → «Start». Усе, що надсилається на email (повідомлення, пропозиції, відгуки, нові заявки), дублюється в Telegram. Можна вимкнути або відключити в кабінеті чи командою `/stop` у боті.

### Як підключити Telegram-бота

1. Створіть бота в [@BotFather](https://t.me/BotFather) і задайте змінні `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_NAME` (ім'я бота без @).
2. Локально: `flask --app run telegram-poll` у другому терміналі — бот отримуватиме повідомлення без webhook.
3. На сервері з HTTPS: задайте `TELEGRAM_WEBHOOK_SECRET` (будь-який випадковий рядок) і `SITE_URL`, потім один раз виконайте `flask --app run telegram-set-webhook`.

Без токена блок Telegram у кабінеті прихований, а повідомлення лише друкуються в консоль.

## Оновлення дизайну

- **Світла тема за замовчуванням.** Темна вмикається кнопкою з місяцем/сонцем у хедері й запам'ятовується в браузері. Системна тема пристрою на сайт не впливає.
- **Новий хедер:** більший, закріплений угорі, з логотипом, кнопкою «Створити заявку» та мобільним меню.
- **Категорії** показані єдиним списком: клік розкриває підкатегорії, а справа вікно з ілюстрацією змінюється залежно від категорії (при наведенні — попередній перегляд). Обрана категорія підставляється в пошук.
- **11 головних категорій і 48 підкатегорій.** Нові категорії (будівництво, ремонт техніки, опалення, меблі, комп'ютери, тварини та інші) додаються до існуючої бази автоматично один раз. Після цього ваші зміни в адмін-панелі (перейменування, видалення) не перезаписуються.
- Ілюстрації лежать у `app/templates/_scenes.html` (SVG, кольори беруться з теми), відповідність категорій до ілюстрацій — у `app/scenes.py`. Для нової головної категорії, створеної в адмінці, показується загальна ілюстрація.

### Денний дайджест

Дайджести надсилає команда `flask --app run send-digest`. Запускайте її раз на день:

- Windows: Планувальник завдань (Task Scheduler) — запуск `venv\Scripts\flask.exe --app run send-digest` у папці проєкту;
- Linux: рядок у `crontab`, наприклад `0 8 * * * cd /шлях/до/проєкту && venv/bin/flask --app run send-digest`.

Для правильних посилань у листах задайте змінну `SITE_URL` (адреса сайту).

### Тести

```bash
python tests/test_flows.py
```

Скрипт проходить основні сценарії: кабінет, заявки, відгуки, чат, адмінку, сповіщення, запрошення, обране й оновлення старої бази. Виконується приблизно за кілька секунд і не чіпає вашу базу.

### Перший адміністратор

Зареєструйтесь на сайті, потім виконайте:

```bash
flask --app run make-admin ваш@email.com
```

### Налаштування (змінні оточення)

| Змінна | Призначення |
|---|---|
| `SECRET_KEY` | секретний ключ (обов'язково змініть на сервері) |
| `MAIL_SERVER`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_USE_TLS`, `MAIL_FROM` | SMTP. Без `MAIL_SERVER` листи лише друкуються в консоль (посилання для підтвердження й відновлення видно там) |
| `REQUIRE_EMAIL_CONFIRMATION=1` | вимагати підтверджений email для заявок, пропозицій, відгуків і чату |
| `SITE_URL` | адреса сайту для посилань у листах, наприклад `https://santimanos.example` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_NAME`, `TELEGRAM_WEBHOOK_SECRET` | Telegram-бот для сповіщень (див. вище) |
| `TIMEZONE` | часовий пояс для показу часу, наприклад `Europe/Madrid` або `Europe/Kyiv` (за замовчуванням UTC) |

## Перед публікацією на сервері

- Задайте `SECRET_KEY`, налаштуйте SMTP і `REQUIRE_EMAIL_CONFIRMATION=1`.
- Вимкніть `debug` і запускайте через Gunicorn + Nginx з HTTPS.
- Ліміти запитів зберігаються в пам'яті процесу: для кількох воркерів або серверів потрібен Redis.
- Перейдіть на PostgreSQL і підключіть Flask-Migrate замість `dbupgrade.py`.
- Налаштуйте резервні копії `santimanos.db` і папки `app/static/uploads`.
- Додайте сторінки політики конфіденційності та згоди на обробку даних (GDPR), а також експорт даних користувача.

## Що можна додати далі
